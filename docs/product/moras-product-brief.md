# Moras 제품 브리프

## 한 줄 정의

Moras는 오픈채팅 이벤트 참가자가 웹앱에 접속해 DB에 미리 등록된 본인을 선택하고, MBTI와 생년월일시를 입력하면 Node.js 만세력 라이브러리가 사주/만세력 정보를 계산하고 Gemini API가 개인 관점별 궁합 점수와 매칭 이유를 생성해 남녀를 1:1로 매칭하는 이벤트용 웹 애플리케이션이다. 입력 원본은 공개 화면에 노출하지 않고 관리자 화면에서만 조회하며, 매칭에는 MBTI와 계산된 만세력 결과를 사용한다.

## 이름의 의미

Moras는 MBTI 기반 성향 분석과 사주, 운명, 기질 해석의 느낌을 함께 담기 위해 선택한 이름이다.

| 요소 | 의미 |
|---|---|
| M | MBTI, Mind, Match |
| Oracle | 사람의 성향과 관계 흐름을 해석하는 상징 |
| S | Saju, Sync, Soul |

## 기획 의도

현재 오픈채팅에서 진행되는 이벤트를 웹 애플리케이션 기반으로 전환한다.
참가자는 별도 설명을 오래 읽지 않고 접속, 본인 선택, MBTI 입력, 생년월일시 입력, 만세력 계산, 제출을 완료할 수 있어야 하며, 운영자는 이벤트 참가자들의 정보를 기반으로 일괄 매칭 결과를 산출할 수 있어야 한다.

핵심 재미는 "나와 가장 잘 맞는 사람은 누구인가?"에 있다. MBTI의 익숙함과 사주의 신비감을 결합해, 가볍지만 몰입감 있는 이벤트 경험을 만든다.

또한 Moras는 NStack을 실제 제품 개발에 적용해 검증하는 파일럿 애플리케이션이다. 제품을 완성하는 과정에서 NStack의 지시서, 검증, 보고, 지식화 흐름이 실전에서도 유효한지 함께 확인한다.

## 핵심 이벤트 흐름

1. 참가자가 Moras 웹앱에 접속한다.
2. DB에 미리 등록된 참가자 목록에서 본인을 선택한다.
3. MBTI를 직접 입력하고 생년월일/출생시간 등 기본 정보를 입력한다.
4. 서버가 `@fullstackfamily/manseryeok`로 만세력을 계산하고 입력 원본은 관리자 화면에서만 조회 가능하게 관리한다.
5. Gemini API가 계산된 만세력 결과와 MBTI를 바탕으로 개인 관점별 방향성 궁합 점수와 이유를 생성한다.
6. 운영자가 전체 참가자 입력 완료 후 일괄 매칭을 실행한다.
7. 시스템은 평균 점수가 높은 조합을 기준으로 모든 참가자를 1:1 매칭한다. 성비가 맞지 않으면 적은 쪽 인원 수만큼 매칭한다.
8. 결과 페이지에서 평균 점수와 1등 하이라이트를 보여준다.
9. 상세 페이지에서 매칭 이유를 확인하고, 남녀 각각이 비밀 투표를 한다.

## MVP 범위

### 참가자 화면

- 이벤트 입장 화면
- 참가자 정보 입력 폼
- DB에 미리 등록된 본인 드롭다운 선택
- MBTI 직접 입력 또는 선택
- 사주 입력용 생년월일, 출생시간, 양력/음력 선택
- 생년월일시, 양력/음력, 출생 지역 또는 경도 입력
- 서버 측 만세력 자동 계산
- 생년월일시 원본 공개 화면 미노출 및 관리자 전용 조회
- 개인정보 및 이벤트 이용 동의
- 제출 완료 화면

### 운영자 화면

- 관리자 패스코드 또는 운영자 전용 접근 키
- 참가자 목록
- 성별/제출 상태 필터
- 참가자별 비밀투표 코드 생성 또는 재생성
- 매칭 점수 계산 실행
- 남녀 매칭 후보 리스트
- 참가자별 상세 점수 breakdown
- 1등 매칭 하이라이트
- 비밀 투표 결과 확인

### 매칭 엔진

- `@fullstackfamily/manseryeok` 기반 만세력 계산
- Gemini API 기반 MBTI/사주 방향성 점수
- 남자 기준 여자 점수
- 여자 기준 남자 점수
- 평균 점수 기반 최종 매칭
- 동일 참가자 중복 매칭 방지
- 성비 불일치 시 적은 쪽 기준 1:1 강제 매칭
- 전체 평균 점수 합이 최대가 되는 최적 매칭
- 운영자 수동 조정 여지

## 초기 점수 모델

정확한 명리학 해석 엔진은 별도 고도화 대상으로 둔다. MVP에서는 `@fullstackfamily/manseryeok`로 만세력을 계산하고, Gemini API를 사용해 MBTI와 계산된 만세력 기반 방향성 점수와 설명 가능한 이유를 생성한다.

| 항목 | 설명 |
|---|---|
| 남자 기준 점수 | 남자 참가자 관점에서 여자 참가자와의 궁합 |
| 여자 기준 점수 | 여자 참가자 관점에서 남자 참가자와의 궁합 |
| 평균 점수 | 두 점수의 평균. 최종 매칭 기준 |
| 매칭 이유 | Gemini가 생성하되, 운명론적 단정 표현은 피함 |

Gemini 평가는 개인 한 명의 관점에서 반대 성별 대상 전체를 하나씩 점수화한다. 최종 남녀 조합 점수는 `남자 -> 여자` 점수와 `여자 -> 남자` 점수의 평균으로 계산한다.

상세 이벤트 플로우는 `docs/product/moras-event-flow-spec.md`를 기준으로 한다.

## NStack 파일럿 관점

Moras 개발 과정에서는 제품 기능뿐 아니라 NStack 자체도 검증한다.

- 신규 프로젝트 초기화가 재현 가능한지 확인
- Supabase, Netlify, GitHub, LLMWiki 연결 흐름 검증
- 각 작업의 지시서와 보고서 작성 품질 확인
- SwarmVault 검색이 다음 작업에 실제로 도움이 되는지 확인
- 개발 중 발견한 NStack 개선점을 회고와 LLMWiki에 기록

## 중요한 제품 원칙

- 참가자 경험은 짧고 직관적이어야 한다.
- 결과는 "재미있는 이벤트"로 느껴져야 하며, 결정론적 운명 판정처럼 표현하지 않는다.
- 사주 해석은 민감할 수 있으므로 과도한 단정 표현을 피한다.
- 개인정보 입력 항목은 최소화하고, 운영 목적을 명확히 고지한다.
- 생년월일시 원본은 공개 화면에 노출하지 않고 관리자 화면에서만 조회한다.
- 운영자가 결과를 검토하고 조정할 수 있어야 한다.
- 참가자 화면은 회원가입/로그인 없이 누구나 접속 가능한 공개 웹앱으로 시작한다.
- 운영자 페이지는 관리자 패스코드 또는 운영자 전용 접근 키로 보호한다.
- 참가자 인증이 없으므로 공개 화면에 민감한 참가자 정보를 노출하지 않는다.
- 비밀투표 코드는 투표 당사자와 운영자만 알 수 있게 하고, DB에는 원문 대신 해시만 저장한다.
- Gemini API 키와 Supabase service role key는 클라이언트에 노출하지 않는다.
- `@fullstackfamily/manseryeok` 결과는 우선 운영자 생년월일시 샘플로 포스텔러와 비교 검증한다.

## 아직 결정해야 할 것

- 웹앱 기술 스택
- `@fullstackfamily/manseryeok` 검증 결과가 부족할 때의 대체 방식
- 참가자에게 결과를 직접 보여줄지, 운영자만 볼지
- 오픈채팅 이벤트 운영 방식과 결과 발표 방식
